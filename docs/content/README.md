# اعتماد المحتوى المضمّن

هذه الوثائق تجعل كل نص ديني أو ترجمة أو تفسير أو تسجيل أذان مضمّن **قابلاً للتتبع** قبل نشره في AAB إنتاجي.

## الملفات

| الملف | وظيفته | من يعدله |
|---|---|---|
| `content_manifest.json` | جرد مولّد آليًا للمسار والبصمة والحجم وحالة الإنتاج. | لا يعدل يدويًا؛ يولده `scripts/generate_content_manifest.py`. |
| `content_approvals.json` | مصدر ورخصة ونسبة ومراجعة مستقلة لكل أصل. | مراجع المحتوى/الترخيص فقط بعد التحقق. |
| `../../scripts/verify_content_manifest.py` | يتأكد من التطابق ويمنع artifact إنتاجي غير معتمد. | CI ومسؤول الإصدار. |

## دورة الاعتماد

1. يتحقق المراجع من **المصدر الأولي** للأصل، لا من اسم ملف أو مصدر ثانوي فقط.
2. يثبت حق التوزيع في تطبيق Android، ونص الترخيص، وواجب النسبة أو الرابط إن وجد.
3. يراجع المختص المحتوى الديني أو النص أو التصنيف في النسخة واللغة المضمّنة.
4. يضيف سجلاً تحت `approvals` بالمفتاح المطابق لـ`id` في manifest.
5. يعيد توليد manifest ويشغّل الفاحص العادي.
6. لا يُستخدم `--production` قبل اكتمال كل أصل؛ نجاحه هو بوابة artifact الإنتاج.

## مثال اعتماد

```json
{
  "approvals": {
    "feature_feature_quran_src_main_assets_quran_ayahs_txt": {
      "source": "رابط ثابت للمصدر أو استشهاد أولي",
      "licence": "اسم الرخصة والنص أو الرابط",
      "attribution": "النص المعروض للمستخدم إن طُلب",
      "religious_review": "اسم المراجع، نطاق المراجعة، وتاريخها",
      "notes": "إصدار المصدر أو القيود المعروفة"
    }
  }
}
```

> لا تحوّل حالة أصل إلى «approved» يدويًا. المولّد لا يمنح الحالة إلا عند وجود المصدر والرخصة والمراجعة. أما الملفات التي تحمل `sample` فتبقى محجوبة إلى أن تستبدل بحزمة إنتاج معتمدة.

## أوامر التحقق

```bash
python3 scripts/generate_content_manifest.py
python3 scripts/verify_content_manifest.py
python3 scripts/verify_content_manifest.py --production
```

الأمر الأخير مصمم للفشل حاليًا حتى يكمل الاعتماد البشري لكل أصل. هذا الفشل مقصود: يمنع إعلان أو نشر نسخة إنتاجية بمحتوى غير موثق.
