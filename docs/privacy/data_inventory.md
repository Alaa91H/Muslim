# جرد البيانات والخصوصية لإصدار v1

> **الحالة:** خط أساس تقني؛ لا يُعتمد نموذج Google Play Data safety حتى يراجع مسؤول الخصوصية كل SDK وطلب شبكة في artifact الإنتاجي.  
> **المبدأ:** البيانات محلية افتراضيًا، والشبكة والقدرات الحساسة اختيارية ومتصلة بسياق واضح للمستخدم.

## 1. بيانات التطبيق

| فئة البيانات | أمثلة | التخزين المتوقع | مشاركة افتراضية | حالة التحقق |
|---|---|---|---|---|
| تفضيلات العبادة | طريقة الحساب، الموقع المحفوظ، إعدادات الأذان، التعديلات الهجرية. | DataStore/تخزين التطبيق. | لا مشاركة افتراضية. | يحتاج مطابقة مع الكود وData safety. |
| تقدم القراءة والدراسة | علامات القرآن، التقدم، ملاحظات، بطاقات، سجل التسبيح. | Room/تخزين التطبيق. | لا مشاركة افتراضية. | يحتاج مراجعة retention/export. |
| ملفات محتوى وتنزيل | تلاوات أو ترجمة/تفسير يختارها المستخدم. | مساحة التطبيق المحلية. | طلب من المزود المختار فقط عند طلب المستخدم. | يحتاج مصدر كل endpoint ورخصته. |
| موقع تقريبي/دقيق | إصلاح GPS اختياري لتحديد مواقيت/قبلة. | يستخدم للحساب؛ لا يفترض تخزينه أو رفعه دون مراجعة. | لا مشاركة افتراضية. | يحتاج تدقيق runtime وnetwork. |
| إعدادات الأجهزة | Wear snapshot، إعدادات bridge المنزلية، حالة إشعار. | محلي؛ سر bridge مشفر حسب وثائق المشروع. | Wear/endpoint يختاره المستخدم فقط. | يحتاج اختبار وتدقيق SDK. |
| بيانات دعم اختيارية | وصف عيب، جهاز، سجل يختاره المستخدم. | تحدد قناة الدعم قبل الإنتاج. | فقط عند إرسال المستخدم صراحة. | قرار منتج مطلوب. |

## 2. الصلاحيات المعلنة

| الصلاحية | الغرض المشروع | وقت الاستخدام/البديل | قرار v1 |
|---|---|---|---|
| `ACCESS_COARSE_LOCATION` و`ACCESS_FINE_LOCATION` | إصلاح موقع اختياري للمواقيت والقبلة. | عند طلب المستخدم من شاشة الموقع؛ إدخال يدوي بديل. | راجع الإفصاح والرفض. |
| `POST_NOTIFICATIONS` | إظهار الأذان والتذكيرات. | طلب في سياق التنبيهات؛ يظل الاستخدام اليدوي متاحًا. | راجع Android 13+. |
| `SCHEDULE_EXACT_ALARM` | جدولة الأذان/التنبيهات الدقيقة عند السماح. | بطاقة الجاهزية تشرح عدم السماح؛ fallback غير دقيق إن صُمم. | اختبار جهاز إلزامي. |
| `RECEIVE_BOOT_COMPLETED` | إعادة جدولة التنبيهات بعد إعادة التشغيل. | لا بديل عملي للوظيفة. | تحقق من receiver وإفصاح الخصوصية. |
| `VIBRATE` و`WAKE_LOCK` | تنبيه الأذان واستمرار التشغيل القصير. | مرتبطان بالتنبيه فقط. | تحقق من عدم إساءة الاستخدام. |
| `FOREGROUND_SERVICE*` | تشغيل الأذان/الصوت/العد التنازلي في السياقات المعلنة. | يقتصر على نوع الخدمة الصحيح. | راجع قيود API الحديثة. |
| `ACCESS_NOTIFICATION_POLICY` | عدم الإزعاج الاختياري بعد الأذان. | لا يفعل بلا منح المستخدم. | إعلان واضح. |
| `SYSTEM_ALERT_WINDOW` | سطح ذكر/تذكير اختياري إن فُعّل. | لا يمنع العبادة الأساسية عند الرفض. | مراجعة متجر وصياغة. |
| `BIND_NOTIFICATION_LISTENER_SERVICE` | سلوك إشعار اختياري فقط. | يجب توثيق المسار وشاشة الإفصاح. | تدقيق P0 قبل الإطلاق. |
| `RECORD_AUDIO` | ميزة تنقل صوتي بنقرة صريحة. | لا يستخدم في الخلفية؛ بديل لمس كامل. | راجع الإفصاح والرفض. |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | إرشاد اختياري لموثوقية الأذان. | لا يفرض على المستخدم. | اختبار OEM وسياسة Play. |
| `REQUEST_INSTALL_PACKAGES` | تحديث/تثبيت يختاره المستخدم. | يفتح مثبت النظام؛ لا تنزيل صامت. | تحقق من ملاءمة السياسة. |
| `INTERNET` | تنزيلات واختبارات تحديث وخرائط وbridge اختيارية. | لا حاجة للشبكة للمسارات الأساسية المحددة. | جرد endpoints وSDKs. |

## 3. الاتصالات الخارجية التي تحتاج مصفوفة Endpoint

| الاستخدام | نقطة القرار | ما يجب تدقيقه قبل الإنتاج |
|---|---|---|
| تنزيل التلاوات/الترجمة/التفسير | اختيار المستخدم لمزود/ملف. | HTTPS، المصدر والرخصة، سياسة المزود، حجم/تجزئة، وعدم إرسال بيانات غير لازمة. |
| خرائط/مساجد | فتح المستخدم للوظيفة. | مزود الخرائط/البحث، عنوان IP والبيانات المرسلة، شروط الاستخدام. |
| فحص التحديث | إعداد المستخدم أو توقيت معلن. | endpoint GitHub، تجنب معرفات تتبع، توقيع/تجزئة artifact. |
| Wear OS | Opt-in pairing. | payload الفعلي، Google Play services، عدم نقل موقع/صوت دون تصريح. |
| bridge المنزلية | Endpoint HTTPS يختاره المستخدم. | URL validation، سر مشفر، حمولة الحد الأدنى، retry وعدم التسريب في logs. |

## 4. قائمة تحقق Data safety

لا يملأ نموذج المتجر اعتمادًا على هذا الملف وحده. يجب أن ينفذ مسؤول الخصوصية البنود التالية لكل artifact مرشح:

1. قراءة كل manifest مدمج وdependency tree وSDK guidance.
2. مراقبة الطلبات الشبكية للمسارات الاختيارية والرفض والإيقاف.
3. مطابقة كل نوع بيانات مع الجمع/المشاركة والغرض والتشفير والإلزام/الاختيار.
4. مراجعة سياسة الخصوصية داخل التطبيق وعلى URL عام فعال.
5. حفظ تصدير CSV أو لقطة النموذج مع release issue.
6. إعادة المراجعة عند إضافة SDK أو صلاحية أو endpoint أو قناة دعم.

## 5. عناصر مفتوحة تمنع إقرار الإنتاج

| المعرف | البند | المالك |
|---|---|---|
| PRIV-001 | تدقيق سلوك `BIND_NOTIFICATION_LISTENER_SERVICE` و`SYSTEM_ALERT_WINDOW` في artifact الإنتاجي وإثبات الحاجة. | قائد تقني + خصوصية |
| PRIV-002 | قرار قناة تقارير الأعطال/الدعم وآثارها على Data safety. | مالك المنتج + خصوصية |
| PRIV-003 | جرد SDKs وendpoints مع سياسات مزودي المحتوى والخرائط. | تقني + خصوصية |
| PRIV-004 | نشر سياسة خصوصية versioned على URL HTTPS عام بالعربية والإنجليزية. | خصوصية/تشغيل |
| PRIV-005 | اختبار حذف/تنظيف البيانات المحلية والتنزيلات وتوثيق أثر Android backup. | QA + تقني |
