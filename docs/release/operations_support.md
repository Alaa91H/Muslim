# التشغيل والدعم بعد الإطلاق

## 1. قنوات الدعم

يدعم الإصدار v1 قناة تواصل موثقة بالعربية والإنجليزية. لا يطلب الدعم موقعًا أو بيانات عبادة أو سجلات جهاز إلا إذا اختار المستخدم إرسالها بعد توضيح الغرض.

| نوع البلاغ | أقل بيانات مفيدة | بيانات لا تطلب افتراضيًا | المالك |
|---|---|---|---|
| وقت صلاة | المدينة/إحداثيات يكتبها المستخدم، المنطقة الزمنية، طريقة الحساب، إصدار التطبيق. | سجل مواقع مستمر أو هوية المستخدم. | QA + محتوى |
| أذان/إشعار | نوع الجهاز وAndroid، حالة بطاقة التحقق، القناة/مستوى المنبه، إصدار التطبيق. | تسجيل صوت/سجل كامل دون موافقة. | تقني + QA |
| محتوى/ترجمة | المعرف أو لقطة النص ومصدر الاعتراض. | معلومات شخصية. | محتوى |
| تنزيل/صوت | اسم المزود، رسالة الخطأ، مساحة تقريبية إن اختار المستخدم. | ملفات خاصة. | تقني |
| خصوصية | وصف الطلب والبلد/القانون عند الحاجة. | أي بيانات لا تعالج الطلب. | خصوصية |

## 2. تصنيف الاستجابة

| الدرجة | أمثلة | الإجراء |
|---|---|---|
| P0 | وقت خاطئ متكرر، أذان يضلل المستخدم، نص ديني خاطئ/بلا حق توزيع، تسريب بيانات، crash يمنع الدخول. | إيقاف rollout أو ميزة عند الحاجة، incident، إصلاح hotfix، مراجعة سبب جذري. |
| P1 | خلل في تنزيل أو مسار إعداد مهم مع بديل، مشكلة إتاحة في شاشة غير مانعة. | إصلاح في أقرب RC، نشر workaround واضح. |
| P2 | تحسين أو خلل محدود. | جدولة في backlog وفق الأثر. |

## 3. بروتوكول hotfix

1. فتح incident وتعيين P0/P1 ومالك واضح.
2. تجميد الميزات غير اللازمة وإنشاء فرع إصلاح.
3. إضافة اختبار رجعي أو حالة جهاز/محتوى تمنع التكرار.
4. تشغيل جودة CI ومصفوفة Smoke المرتبطة بالخلل.
5. تحديث سياسة الخصوصية/Data safety أو سجل المحتوى إن تغير السلوك/المصدر.
6. نشر تدريجي ومراقبة البلاغات قبل توسيع rollout.
7. إغلاق incident بتقرير سبب جذري وإجراء وقائي.

## 4. مؤشرات الإطلاق

| المؤشر | الإجراء عند التدهور |
|---|---|
| crash أو ANR | وقف التوسع، تحليل artifact والإصدار والجهاز، إصلاح قبل زيادة النسبة. |
| بلاغات الأذان | تصنيف حسب OEM/API/قناة/مستوى صوت؛ وقف التوسع عند ظهور نمط P0. |
| شكاوى المحتوى | تحقق من المصدر والرخصة فورًا؛ إيقاف المحتوى أو الوصف عند الحاجة. |
| pre-launch/Play policy | لا يتجاوز التحذير دون قرار مكتوب من المسؤول. |
| طلبات الخصوصية | تعامل عبر مسؤول الخصوصية وفق السياسة المنشورة. |

## 5. الاحتفاظ بالدلائل

يحفظ لكل إصدار: commit، AAB/APK hashes، شهادة التوقيع، نتائج CI، نتائج P0، نموذج Data safety، content manifest، وقرار rollout. لا تحفظ هذه الحزمة بيانات مستخدمين أو سجلات شخصية إلا بموافقة صريحة وسياسة احتفاظ معلنة.
