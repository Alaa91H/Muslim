# حوكمة إصدار v1

> **الهدف:** تحويل جاهزية الإصدار من قرار شخصي أو اعتماد على نجاح البناء إلى قرار موثق متعدد التخصصات.

## الأدوار

| الدور | المسؤولية | حق الإيقاف |
|---|---|---|
| مالك المنتج | النطاق، لغة الوعود، الجمهور المستهدف، قرار الانتقال بين البوابات. | نعم، عند عدم تطابق المنتج مع النطاق. |
| قائد تقني | جودة الكود، التوقيع، بنية AAB، الأمان، التبعيات، وإصلاح العيوب. | نعم، عند عيب P0 أو artifact غير موثوق. |
| قائد QA | خطة الاختبار، نتائج الأجهزة، عيوب الإصدار، واعتماد RC. | نعم، عند فشل سيناريو P0 أو عدم وجود دليل. |
| مراجع المحتوى | مصادر القرآن/الحديث/الذكر/التعلم وحدود الصياغة الدينية. | نعم، عند خطأ محتوى أو نسبة غير موثقة. |
| مراجع الترخيص | حق توزيع النصوص والترجمات والصوت والخرائط والبيانات. | نعم، عند غياب رخصة أو شرط نسبة. |
| مسؤول الخصوصية | Data inventory، السياسة، Data safety، الصلاحيات والـSDKs. | نعم، عند تناقض إفصاح أو جمع غير مبرر. |
| مسؤول الإصدار | تشغيل CI، توقيع production، Play Console، rollout وrollback. | نعم، عند غياب خطة تشغيل أو وصول/مفاتيح آمنة. |

## قواعد فرع الإصدار

| القاعدة | التطبيق |
|---|---|
| فرع الإصدار | ينشأ `release/vX.Y` من `main` بعد اجتياز G0 وG1. |
| التغيير المسموح | إصلاحات العيوب، الترجمات المعتمدة، التوثيق، وتغييرات الامتثال فقط. |
| التغيير المحظور | ميزة جديدة، SDK جديد، صلاحية جديدة، أو محتوى جديد بلا بطاقة تغيير واعتماد. |
| مراجعة الدمج | مراجعة تقنية واحدة على الأقل، ومراجعة إضافية للمحتوى/الترخيص/الخصوصية عند تأثيرها. |
| إصدار مرشح | كل RC يحمل tag واضحًا وسجل تغييرات ونتائج اختبارات وروابط artifacts. |
| العودة | أي عيب P0 يعيد الحالة إلى آخر RC سليم؛ لا يُعالج بتجاوز الاختبار. |

## بطاقة تغيير إلزامية

يوضع هذا القالب في Pull Request أو issue قبل أي تغيير يؤثر في v1.

```markdown
## تغيير v1
- الهدف والمستخدم المتأثر:
- هل يغير ادعاءً في سجل الوعود؟
- هل يضيف/يعدل محتوى أو مصدرًا أو ترخيصًا؟
- هل يضيف صلاحية أو طلب شبكة أو SDK؟
- حالات الاختبار المضافة:
- أثر الخصوصية وData safety:
- موافقة: منتج / تقني / QA / محتوى أو ترخيص / خصوصية (حسب الحالة)
```

## تعريف العيوب

| الدرجة | تعريف v1 | مثال |
|---|---|---|
| P0 | يمنع عبادة أو قراءة/تنبيه أساسي، يفقد بيانات، يخرق الخصوصية/الترخيص، أو يمنع النشر. | أذان صامت بلا تشخيص، وقت صلاة خاطئ متكرر، AAB بتوقيع debug. |
| P1 | وظيفة مهمة تعمل مع خلل أو تجربة مضللة لكن يوجد بديل آمن. | تنزيل لا يعيد المحاولة، تسمية TalkBack غير مفهومة في شاشة ثانوية. |
| P2 | تحسين أو خلل محدود لا يؤثر في بوابة الإنتاج. | تحسين ترتيب بطاقة أو إضافة محتوى اختياري. |

## اجتماع قرار البوابة

يعقد اجتماع قصير عند كل بوابة G0–G6 ويُسجل القرار في release issue مع الروابط. لا تقبل عبارة «يبدو جيدًا» كدليل؛ المطلوب artifact أو نتيجة اختبار أو توقيع مراجعة.

| الحقل | المطلوب |
|---|---|
| الإصدار/RC | tag وcommit وAAB SHA-256. |
| البوابة | G0 إلى G6. |
| عناصر مكتملة | روابط الملفات والتشغيلات والتقارير. |
| الاستثناءات | السبب والمالك وتاريخ الإغلاق وخطة الاحتواء. |
| القرار | انتقال / توقف / رجوع. |
| الموافقون | الأدوار المطلوبة وتاريخ الموافقة. |
