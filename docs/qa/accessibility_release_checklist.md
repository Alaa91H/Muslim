## 2. معايير القبول

| الفحص | المعيار |
|---|---|
| التسميات | كل عنصر تفاعلي يملك وصفًا قصيرًا يشرح هدفه، ولا تنطق خدمات الإتاحة أسماء أيقونات غير مفهومة. |
| الترتيب | ترتيب التركيز يطابق القراءة والمنطق RTL/LTR ولا يزور العنصر نفسه مرتين. |
| اللمس | لا يعتمد مسار P0 على gesture لا بديل له، والأهداف التفاعلية قابلة للوصول. |
| التباين | النصوص والرموز المهمة مرئية في الوضعين الفاتح والداكن ومع التباين العالي. |
| تكبير الخط | لا تُقطع نصوص أو تصبح الأزرار غير قابلة للوصول عند تكبير خط النظام. |
| الصوت والإشعارات | أي رسالة نجاح/فشل حرجة، مثل جاهزية الأذان، قابلة للقراءة بخدمة الإتاحة. |
| اللغة | العربية RTL لا تعكس المعنى أو ترتيب الأرقام/الوقت بصورة مربكة. |

## 3. أدوات الدليل

| الأداة | ما يحفظ مع RC |
|---|---|
| Compose UI Check / Accessibility Scanner | صور النتائج والعيوب المعالجة أو الاستثناءات. |
| TalkBack وSwitch Access | اسم الجهاز وAndroid وتوقيع المختبر ونتيجة كل مسار. |
| Play pre-launch report | رابط التقرير وقرار معالجة كل finding ذي أولوية. |
| اختبارات Compose | روابط نتائج CI واختبارات semantics الجديدة. |

## 4. قاعدة الحجب

أي عيب يمنع الوصول إلى الأذان أو القرآن أو الإعدادات أو فهم رسالة أمان/خصوصية يعد P0 أو P1 بحسب وجود بديل آمن. لا يمر RC إلى الإنتاج مع عيب إتاحة P0.
